# راهنمای اجرای پایپلاین اصلاح‌شده

## ترتیب اجرا (حتماً به همین ترتیب)

از ریشه‌ی پروژه (`Parkinson_AI`)، این فایل‌ها را در پوشه‌ی `pipeline/` قرار دهید
و به همین ترتیب اجرا کنید:

```powershell
cd pipeline
python 01_normalize_rnaseq_GSE165082.py
python 02_train_final_model.py
python 03_external_validation.py
```

فایل `gene_signature_locked.json` باید کنار همین سه اسکریپت (داخل `pipeline/`) باشد.

## پیش‌نیازها

قبل از اجرا، مطمئن شوید این پکیج‌ها نصب هستند (در `venv` فعال):

```powershell
pip install pandas numpy scikit-learn joblib mygene
```

اگر با خطای `ModuleNotFoundError` مواجه شدید، دقیقاً اسم ماژول در پیام خطا را
بعد از `pip install` بزنید.

## خطاهای رایجی که ممکن است ببینید و رفعشان

| خطا | علت احتمالی | راه‌حل |
|---|---|---|
| `FileNotFoundError: data/GSE99039_final_dataset.csv` | مسیر نسبی اشتباه است | حتماً از **داخل ریشه‌ی پروژه** (یا با تنظیم مسیر مطلق در بالای اسکریپت) اجرا کنید، نه از داخل `pipeline/` مستقیم — یا مسیرها را در اسکریپت به `../data/...` تغییر دهید اگر اسکریپت را از داخل `pipeline/` اجرا می‌کنید |
| `ValueError: این ژن‌ها ... پیدا نشدند` | یکی از ژن‌های لیست قفل‌شده در دیتاست نیست | چاپ‌شده در پیام خطا کدام ژن است؛ یا نام ژن در دیتاست فرق دارد (مثلاً alias) یا واقعاً حذف شده |
| `mygene` timeout یا خطای شبکه | سرویس آنلاین mygene.info در دسترس نیست | اتصال اینترنت را چک کنید؛ اگر مکرر خطا داد، نتیجه‌ی mapping را یک‌بار cache کنید (`GSE165082_gene_symbol.csv` قدیمی هنوز قابل استفاده است اگر مطمئنید نگاشتش درست بوده) |
| AUC هنوز غیرمنطقی بالا با Accuracy پایین | مشکل عمیق‌تر از نرمال‌سازی - عدم سازگاری واقعی پلتفرم | اسکریپت ۰۳ خودش هشدار می‌دهد؛ قدم بعدی: ComBat یا quantile normalization بین دو دیتاست |

## نکته‌ی مهم درباره‌ی مسیرها

اسکریپت‌ها با فرض این نوشته شده‌اند که از **ریشه‌ی پروژه** اجرا شوند (یعنی
`python pipeline/01_normalize_rnaseq_GSE165082.py` از پوشه‌ی `Parkinson_AI`،
نه از داخل خود `pipeline/`). اگر ترجیح می‌دهید از داخل `pipeline/` اجرا کنید،
مسیرهای `data/...` و `model/...` را در بالای هر اسکریپت به `../data/...` و
`../model/...` تغییر دهید.

## بعد از اجرای موفق

فایل `model/cv_performance.json` عدد واقعی و قابل‌گزارش (CV-based، نه
training-only) را نگه می‌دارد — این عددی است که باید در بخش Results مقاله
بیاید، نه هیچ‌کدام از فایل‌های قدیمی `final15_model_results.csv` یا مشابه.
